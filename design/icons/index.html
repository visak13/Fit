Interface glyph proof sheet

Every glyph is shown at 16, 24 and 32 pixels on both light and dark backgrounds. The 16 pixel sample is presented first with the same visual slot as the larger sizes.

Parameter demonstration

The same three glyphs are rendered from one geometry source with three stroke and corner settings.

Filled interior marks deliberately use fill="currentColor" so the consuming interface supplies their colour across all three visual directions and both themes. When a glyph file is opened through an image tag, those filled parts render black; that is expected because the application consumes the glyphs inline where colour is set. Do not replace currentColor with a fixed colour merely to improve a standalone preview, because doing so would break the theming the set depends on.

Additional glyphs

  • filter is included so long client, routine and exercise lists can be narrowed without overloading search.
  • rest-interval is included because timed recovery is a first-class step during a coached session.
  • progress-over-time is included so the coach can open a client’s longitudinal training view.
  • drag-handle is included to expose the direct manipulation target used while reordering exercises.
  • sign-out is included for the routine action that disconnects the Google account while preserving local data.
  • sign-out-and-erase-this-device is included for the separately confirmed local wipe action.
  • what-leaves-this-device is included as the permanent destination for reviewing outbound data.
  • protected-clinical-note is included so the encrypted field is visibly different in kind from an ordinary note.

The sign-out and sign-out-and-erase-this-device glyphs are deliberately unrelated in silhouette so the routine and destructive actions cannot be mistaken for a matched pair.
